One call to take a payment. Everything else is a detail.

Kestrel is a payments API in the shape of the language you already write. A charge is one request and one response; refunds, disputes and payouts are the same shape again.

  • All systems operational
  • v1 · 2024-06-11
  • Idempotency on by default
server.jsJavaScript 
import { Kestrel } from "@kestrel/node";

const kestrel = new Kestrel(process.env.KESTREL_KEY);

const charge = await kestrel.charges.create({
  amount: 24800,              // minor units, always
  currency: "eur",
  customer: "cus_8Hk2m",
  source: "tok_visa",
  description: "Order 8QK2",
  idempotency_key: order.id,   // your key, your retry safety
});

console.log(charge.status);   // "succeeded"

API reference

Four resources cover 90% of integrations. Every response carries a request id; quote it in support and we can find the exact trace.

POST /v1/charges Take a payment. Idempotent per key. +
Parameters for creating a charge
FieldTypeNotes
amountintegerMinor units. 24800 is €248.00. Zero is rejected.
currencystringISO 4217, lowercase. 39 currencies supported.
customer optionalstringOmit for a one-off; the charge is still queryable by id.
sourcestringToken from the client SDK. Raw card numbers are never accepted.
metadata optionalobjectUp to 20 keys, 500 characters each. Returns on every read.
POST /v1/refunds Full or partial, against a charge id. +
Parameters for creating a refund
FieldTypeNotes
chargestringThe charge to refund. Required.
amount optionalintegerOmit to refund the full remaining amount.
reason optionalstringrequested_by_customer or fraudulent.
POST /v1/customers Create a customer and attach methods. +
Parameters for creating a customer
FieldTypeNotes
emailstringUsed for receipts and disputes evidence.
source optionalstringAttaches and pre-authorises a payment method.
metadata optionalobjectSame 20-key limit as charges.
GET /v1/charges/{id} Read a charge. Never expires. +

Charges are immutable. If something needs to change, refund it and create a new charge — the audit trail stays readable.

Idempotency

Send Idempotency-Key with every write. If we have seen the key before, we return the original response — no second charge, no reconciliation work on Monday.

  • Keys are scoped to your account and retained for 30 days.
  • Reusing a key with different parameters returns 409 idempotency_conflict.
  • If two identical requests race, the loser is held until the winner finishes, then receives the same body.

Webhooks

Delivered at least once, in order per object, with the object id in the object field. Verify the signature, fetch the object, do not act on the payload alone.

verify.jsJavaScript 
import { Kestrel } from "@kestrel/node";

app.post("/webhooks/kestrel", kestrel.webhooks.verify({
  secret: process.env.KESTREL_WEBHOOK_SECRET,
  handler(req, res) {
    const event = req.body;        // already verified
    enqueue(event.type, event.data.object.id);
    res.sendStatus(200);          // fast, then work
  },
}));

Errors

One shape, always. Branch on error.type, never on the message, and log error.request_id.

Error response · 402 Payment RequiredJSON
{
  "error": {
    "type": "card_declined",
    "code": "do_not_honor",
    "message": "The issuer declined this charge.",
    "decline_code": "generic_decline",
    "request_id": "req_7Kd1",
    "retryable": false
  }
}
  • 4xx means the request is wrong — fix the call, do not retry it.
  • 409 is an idempotency conflict — check whether the first attempt actually landed.
  • 429 carries Retry-After in seconds. Honour it; the limit is per token, not per account.
  • 5xx is safe to retry with the same idempotency key.

Changelog

We publish every behaviour change here before it ships, with a migration note where one is needed.

18 Sep 2026

Partial refunds can be issued against a disputed charge

Previously rejected with charge_disputed. The undisputed remainder is now refundable; the disputed amount is still held by the issuer.

addbehaviour
02 Sep 2026

Idempotency keys now scoped per account

Keys written under a previous scope stop matching. Nothing breaks, but replaying an old request will create a new charge. We recommend a namespaced key such as order:{id}.

breakingmigration note
21 Aug 2026

New endpoint: disputes evidence upload

Attach receipts, delivery proof and correspondence to a dispute before the response deadline. Accepts PDF, PNG and JPEG up to 12 MB per file.

add
05 Aug 2026

Sandbox now mirrors production decline codes

Test cards return the same decline_code values as live issuers, so error handling can be written before go-live.

fix

Get a test key

Keys are issued per environment. A test key cannot move money; a live key requires an approved account and an explicit activation call.
