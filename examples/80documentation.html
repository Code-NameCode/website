Build against Quill

Quickstart#

Every request is a JSON POST or GET against https://api.quill.dev/v3, authenticated with a bearer token. Start by creating a document:

BASH create-document.sh 
# Your key is created in Dashboard → Developers → Keys
curl https://api.quill.dev/v3/documents \
  -X-Quill-Key: qk_live_8f2c… \
  -Content-Type: application/json \
  -d {
    "title": "Lease agreement — 41 Ellery Street",
    "body": "b64://aW5pdmlkYWJsZQ==",
    "signers": [{ "name": "R. Ellery", "email": "r.ellery@example.com", "order": 1 }]
  }

The response carries a document object and the version number, which starts at 1 and increments on every successful change:

JSON 201 Created 
{
  "id": "doc_9Kd2mQ7xLp",
  "title": "Lease agreement — 41 Ellery Street",
  "version": 1,
  "status": "awaiting_signature",
  "signers": [
    { "name": "R. Ellery", "state": "sent", "sent_at": "2026-11-02T09:14:22Z" }
  ],
  "created_at": "2026-11-02T09:14:21Z"
}
Send the key in the header, not the query string. Keys in URLs end up in access logs. X-Quill-Key is the only supported method; the Authorization: Bearer form is reserved for OAuth tokens.

Authentication#

Quill uses two credential types. Pick one per integration and keep them scoped to the narrowest thing they need.

  • API keys (qk_live_…, qk_test_…) — long-lived, created per environment, with scopes. Use for server-to-server calls.
  • Session tokens (qs_…) — 15 minutes, issued by POST /v3/sessions. Use for the browser signing widget so keys never leave your server.

Keys can be rotated with a 24-hour overlap: create the new key, deploy it, then revoke the old one. Requests are rejected if two keys share a scope and Idempotency-Key is missing.

Endpoints#

All paths below are relative to https://api.quill.dev/v3. All bodies are JSON. All timestamps are ISO 8601 in UTC.

GET /documents/{document_id} documents:read

Fetch a single document. Pass ?include=signatures,audit to expand related objects; each expansion adds roughly 40 ms.

POST /documents documents:write

Creates a document and, if signers are supplied, sends signature requests immediately. Send an Idempotency-Key header to make retries safe: repeating a request with the same key returns the original document rather than creating a second one.

Body parameters
FieldTypeRequiredNotes
titlestringYes1–180 characters
bodystringYesRaw text, b64://… for binary, or url://… to fetch
signersarrayNoMax 20; each needs name, email, order
collection_idstringNoDefaults to your unfiled collection
expires_in_daysintegerNo1–365, default 30
metadataobjectNoUp to 20 keys, 500 characters each
PATCH /documents/{document_id} documents:write

Updates only the fields you send and creates a new version. A document that has been fully signed is immutable; attempting an update returns document_locked.

DELETE /documents/{document_id} documents:write

Soft-deletes for 30 days, then hard-deletes. A restore is possible within the window via POST /documents/{id}/restore. Signed documents are retained for the length of your retention policy regardless.

Errors and rate limits#

Errors return a non-2xx status, a machine-readable code, and a human message that is safe to log but not to show to end users.

JSON 422 Unprocessable Entity 
{
  "error": {
    "code": "signer_sequence_invalid",
    "message": "Signer 2 must have an order greater than or equal to signer 1.",
    "param": "signers[1].order",
    "request_id": "req_4Lp8v2Zq"
  }
}
All error codes in v3.4
HTTPCodeMeaningRetry?

403scope_insufficientKey lacks the scope for this callNo
404document_not_foundNo document with that id in this environmentNo

429rate_limitedToo many requests for this keyYes, honour Retry-After
503upstream_timeoutSigning provider did not respondYes, exponential backoff
Retry 429 and 503 only. Retrying a 422 will never succeed and will cost you quota. On 429, read the Retry-After header rather than guessing — the value is in seconds and is authoritative.

Webhooks#

Quill posts a JSON payload to your endpoint when a document changes state. Deliveries are signed so you can verify the source.

TYPESCRIPT verify.ts 
import { createHmac, timingSafeEqual } from "node:crypto";

export function verify(raw: Buffer, header: string, secret: string) {
  const expected = createHmac("sha256", secret).update(raw).digest();
  const provided = Buffer.from(header, "hex");
  return provided.length === expected.length
    && timingSafeEqual(provided, expected);
}
  • Events: document.created, document.sent, document.signed, document.viewed, document.completed, document.expired.
  • Signature header: Quill-Signature: t=<unix>,v1=<hex>. Reject if the timestamp is more than five minutes old.
  • Return 2xx within five seconds. Anything else is retried with exponential backoff for 24 hours.
