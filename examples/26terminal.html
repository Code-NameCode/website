rootkit.sh // deploy in one command

A single static binary that builds your project, runs your migrations, replaces the running process and keeps the last five releases on disk. No agent to install, no control plane to pay for, no dashboard to open at 2 a.m.

curl -fsSL https://get.rootkit.sh | sh
install.sh

$ rootkit deploy --env production

→ migrating  0031_add_region  ok  0.8s
→ draining   12 connections  ok  0.2s
→ switching  symlink → releases/8f3c1a2  ok  0.0s
→ health      200 /healthz  ok  0.3s
✓ live on https://app.example.com  rev 8f3c1a2 · 1.4s

01 / commands

Six verbs cover day-to-day shipping. Everything takes --env and a dry-run flag; nothing touches the machine until it prints the plan and you confirm it.

Command reference
commandwhat it doescommon flags
rootkit deployBuild, migrate, switch, health-check, and keep the previous release warm for an instant rollback.--dry-run --no-migrate
rootkit rollbackPoint the symlink at the previous release and restart. Under two seconds, no rebuild.--to rev --list
rootkit logsFollow stdout of the running process, or of any release on disk. Colour is off when piped.--since 10m --grep
rootkit statusCurrent release, health, migrations applied, disk use. Exit code is meaningful in CI.--json --watch
rootkit initWrite a rootkit.toml from an existing repository, guessing the build and start commands.--force
rootkit pruneDelete old releases, caches and stale images. Dry-run by default.--keep 5

03 / rootkit.toml

One file, committed to the repository. It is read on every command, so CI and your laptop make the same decisions.

rootkit.toml
[app]
name      = "checkout-api"
build     = "make release"
start     = "./bin/server --port $PORT"
health    = "GET /healthz"
keep      = 5

[migrate]
command = "./bin/migrate up"
lock    = true          # one deploy at a time

[host]
drain_timeout = "15s"      # stop accepting, finish serving
user         = "rootkit"
run_dir      = "/srv/checkout"

[env.production]
NODE_ENV = "production"
LOG      = "info"

[env.staging]
NODE_ENV = "production"
LOG      = "debug"
keep
Releases retained on disk. Five is the default; each is about 40 MB for this app.
drain_timeout
How long in-flight requests get to finish before the old process is sent SIGTERM.
lock
Serialises deploys with a file lock. Turn it off only if two machines cannot write the same directory.
health
Polled every 250 ms for up to 10 s. A non-2xx aborts and rolls back automatically.
env.*
Per-environment variables. Secrets are not stored here — use rootkit secret set.
user
The process drops privileges to this user after start. It is the only account that needs write access.

05 / man rootkit

The parts people ask about, in the words of the man page.

MANUALrootkit 1
NAME
rootkit — build, migrate and release a service on a single machine.
SYNOPSIS
rootkit <command> [flags]
DESCRIPTION
Each release is written to releases/<rev>/ and activated by moving a symlink. The switch is atomic, so a load balancer never sees a half-written release. If the health check fails, the previous symlink is restored and the failed release is kept for inspection.
EXIT STATUS
0 success · 1 the command ran but reported a problem (degraded health) · 2 the command could not run (no lock, bad config, unreachable host).
FILES
rootkit.toml configuration · releases/ kept builds · current the active symlink · rootkit.log append-only audit of every command.
ENVIRONMENT
ROOTKIT_ENV default environment · ROOTKIT_LOCK override lock path · NO_COLOR disable colour, as per any sane tool.
EXAMPLES
Ship without thinking: rootkit deploy. Ship safely: rootkit deploy --dry-run. Undo: rootkit rollback --list then rootkit rollback --to 8f3c1a2.
BUGS
Report with the output of rootkit status --json and the contents of rootkit.log. The maintainers read everything; the median reply is 40 minutes.

06 / install

One static binary, 9 MB, no runtime dependencies. It works the same on a Raspberry Pi and a 96-core build box.

# without the pipe
# prefer to read before you run it
curl -fsSLo rootkit https://get.rootkit.sh/v3.4.1/rootkit
less rootkit                    # read it, if you like
chmod +x rootkit
sudo mv rootkit /usr/local/bin/

# verify the release you just installed
rootkit --version
# rootkit 3.4.1 (sha256 8f3c1a2…)

Every release is signed. rootkit verify checks the signature offline against a key in the repository.
